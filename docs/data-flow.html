How a RADET becomes the live dashboard

The watcher collects each new combined RADET from Azure, keeps only the programme cohort, and publishes the totals. Patient-level data never leaves your computer.

Your part

Nothing day to day, once blob_settings.json holds the storage connection string. As a backup you can still save a RADET into C:\Users\user\ViiV_Python_M&E\RADET_inbox yourself; any .xlsx name works.

What runs automatically

  • Every 15 minutes the watcher asks Azure for the newest RADET and downloads it only if its ETag has changed.
  • The analysis keeps State = Yobe, ages 10–19 and the 7 supported facilities, and drops every other row.
  • It then builds the indicators and the Excel report.
  • The sanitizer strips patient records, then the result is pushed.
  • Netlify rebuilds the site and open dashboards pick up the new numbers.

What stays private

Client records, hospital numbers, patient IDs and case manager names stay in data-private\. That folder is excluded from git, and the sanitizer refuses to publish if any of those fields slip through. The Azure connection string stays in blob_settings.json on this computer.

If the site doesn't update

  • Open watch_radet.log to see which step failed. "Azure check failed" points to the connection string or the network.
  • A file in RADET_inbox\failed\ means the analysis could not read it.
  • No Python window in the taskbar means the watcher isn't running. Start ViiV RADET Watcher from the Startup folder.
